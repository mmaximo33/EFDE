# EFDE | Sistema de traducciones (i18n)

Este documento describe cómo funciona el sistema de traducciones de EFDE y cómo mantener los archivos de idioma.

## Resumen

- El código y los ficheros generados en `bin/.tmp` están escritos en **inglés** (idioma base).
- Si el idioma configurado en el host (`HOST_I18N` en `bin/cfg.host`) es distinto del idioma por defecto (`I18N_DEFAULT` en `bin/cfg.core`), al arrancar se **aplican traducciones** sobre los ficheros de `bin/.tmp`: se sustituye cada cadena origen por su traducción según los archivos en `console/<módulo>/i18n/<locale>`.
- Cada **módulo** (common, efde, implementation/*, service/*) tiene su propio directorio `i18n/` con un archivo por idioma (p. ej. `es_ES.csv`, `pt_BR.csv`, `fr_FR.csv`, `de_DE.csv`). Las traducciones se aplican solo a los ficheros `.tmp` de ese módulo.

## Cuándo se aplican las traducciones

- **Condición:** `HOST_I18N` ≠ `I18N_DEFAULT` (por ejemplo, idioma por defecto `en_US` y host `es_ES`).
- **Momento:** Durante el arranque, después de cargar módulos y generar shortcuts, y antes de cargar el menú.
- **Dónde:** Solo se modifican ficheros en `DIRECTORY_TMP` (p. ej. `bin/.tmp`), con nombre `$DIRECTORY.*` (p. ej. `common.*`, `efde.*`). No se tocan los fuentes en `console/`.

## Formato de los archivos i18n (CSV)

- **Ubicación:** `console/<módulo>/i18n/<locale>.csv`. Ejemplo: `console/common/i18n/es_ES.csv`.
- **Idiomas:** `en_US` (base, sin archivo de traducción), `es_ES`, `fr_FR`, `pt_BR`, `de_DE`. Códigos con guión bajo (idioma_PAÍS) para consistencia.
- **Formato:** Una línea por entrada, con **dos campos entre comillas dobles**, separados por coma (CSV de dos columnas).

```text
"texto en inglés tal cual está en el código","texto traducido"
```

- **Columna 1 (origen):** Debe coincidir **exactamente** con la cadena que aparece en el código (incluidos espacios y variables como `$FILE_PATH`, `$DIR_PATH`).
- **Columna 2 (destino):** Cadena que se escribirá en su lugar en los ficheros `.tmp`.

### Comas y comillas dentro del texto

- **Comas dentro de un campo:** Están permitidas. El sistema interpreta el archivo como CSV: solo se separa por la coma que está **fuera** de las comillas. Ejemplo: `"Hello, user","Hola, usuario"` se parsea correctamente.
- **Comilla doble dentro de un campo:** Se escribe **dos comillas seguidas** `""`. Ejemplo: `"Say ""hi""","Di ""hola"""` → origen `Say "hi"`, destino `Di "hola"`.
- **Saltos de línea:** Se pueden usar `\n` en el texto; el sistema los trata como en el código.

### Caracteres especiales en sed

El sistema **escapa automáticamente** los caracteres especiales de `sed` en origen y destino (por ejemplo `\`, `&`, `[`, `]`, `*`, `.`, `^`, `$`, `#`). No es necesario escapar manualmente en los archivos i18n.

## Coincidencia exacta con el código

- La traducción se aplica por **sustitución literal**: se busca la cadena origen en los ficheros `.tmp` y se reemplaza por la destino.
- Si cambias el texto en el código (por ejemplo, de `$PATH` a `$DIR_PATH`), debes **actualizar** el archivo i18n: la línea con el texto antiguo dejará de hacer match; añade una línea con el texto nuevo y la traducción correspondiente.
- Ejemplo en **common**: los mensajes de `directory` y `file` usan `$DIR_PATH` y `$FILE_PATH`. En i18n deben aparecer exactamente:
  - `"Error: Path '$DIR_PATH' does not exist.","Error: La ruta '$DIR_PATH' no existe."`
  - `"Error: Path file '$FILE_PATH' does not exist.","Error: El archivo '$FILE_PATH' no existe."`
  - `"Removed: $DIR_PATH","Eliminado: $DIR_PATH"` y análogo para `$FILE_PATH`.

## Dónde hay i18n en el proyecto

| Módulo            | Ruta i18n                          |
|-------------------|------------------------------------|
| common            | `console/common/i18n/`            |
| efde              | `console/efde/i18n/`              |
| implementation/* | `console/implementation/<nombre>/i18n/` (laravel, symfony, wordpress) |
| service/*         | `console/service/<nombre>/i18n/`  (docker, mysql) |

Cada uno tiene, si aplica, archivos por idioma (p. ej. `es_ES.csv`, `fr_FR.csv`, `pt_BR.csv`, `de_DE.csv`). Las traducciones se aplican solo a los ficheros generados de ese módulo.

## Añadir o corregir traducciones

1. Localiza el **módulo** (common, efde, implementation/..., service/...).
2. Abre o crea `console/<módulo>/i18n/<locale>.csv` (p. ej. `es_ES.csv`).
3. Añade o edita una línea: `"texto exacto del código","traducción"`.
4. Comas y comillas dentro del texto: formato CSV (comas dentro de las comillas; `""` para una comilla literal).
5. No escapes caracteres para sed; el sistema lo hace por ti.

## Depuración (DEBUG_I18N)

Para ver en arranque qué directorios y archivos i18n se revisan y qué sustituciones se aplican, configura `DEBUG="true"` y `DEBUG_I18N="true"` en `bin/cfg.core`. Documentación completa del modo debug: **[debug-workflow.md](debug-workflow.md)**.
